Integrations

Follow the order across your tools.

PayPal confirms the payment. Your store records delivery. CrashCart brings those records together and uses AI to help investigate a missed promise. Explore each tool’s role and what you’ll need to use it.

How it connects

How each integration helps

CrashCart’s code checks payment and delivery against the promise. The AI helps with investigation; the records decide the result.

PayPal Sandbox

Saved records in public example
What it does
Creates and captures CrashCart’s own test orders, then reads the payment back independently. Payment notifications are verified in separately configured runs.
Where to use it
A configured workspace with PayPal Sandbox details. The public example shows saved records from one earlier test checkout.
Good to know
Test money only. The public site never starts a checkout or contacts PayPal.

Background investigation · DeepSeek on Modal

Saved text in public example
What it does
A DeepSeek model, hosted on Modal, works through a case in the background within fixed limits: it reads the records and suggests next steps.
Where to use it
A configured workspace. The public example can show one saved investigation from a separate, earlier, dated case.
Good to know
It never decides the payment or delivery result, and the public site never calls it.

AG Studio

Configured workspace
What it does
Shows the payment, delivery and investigation records linked to each other, so you can follow one order across systems.
Where to use it
A licensed, configured workspace.
Good to know
Not part of the public example.

Bryntum Scheduler (Community)

Configured workspace
What it does
Lays out delivery timing on a timeline, so the gap between payment, ticket and deadline is visible at a glance.
Where to use it
A configured workspace.
Good to know
Not part of the public example, which uses its own simple timeline.

KERNEL

Separately authorised
What it does
Runs a remote test checkout and records it, so the customer’s side of the order is captured too.
Where to use it
Only in runs that have been separately authorised.
Good to know
Not part of the public example. The public site starts no remote session.

Postman

Configured workspace
What it does
Checks CrashCart’s API responses and the records it exports.
Where to use it
Against a configured workspace.
Good to know
Not part of the public example. The downloads there are saved files, and downloading them doesn’t call any service.

Shopify and WooCommerce readers

Preview
What it does
Would read orders and fulfilment from a real store, in place of the owned workshop test store.
Where to use it
A separate preview. It has never been connected to a real store.
Good to know
There’s no install, app listing or connect flow today.

Before you start

What you can use today

  • Test payments onlyEvery payment is PayPal Sandbox test money. The one owned test case is a USD 29 workshop ticket, promised within 60 seconds.
  • Store setupStore connectors are a preview. App installation, customer accounts and store billing aren’t available yet.
  • Private workspace accessThe connected workspace uses an access key from its owner. This public example opens without one.
  • A recorded exampleExplore saved records here. A new payment or AI investigation runs only in a configured workspace.
